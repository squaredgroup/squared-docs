Préparer une modification Velo ou de code

Recherchez les dépendances avant de renommer un élément ou de changer une connexion.

Une intervention réservée aux personnes habilitées

Un élément de page ou un champ CMS peut être utilisé par du code. Le fait qu’un nom soit visible dans l’éditeur ne signifie pas qu’il peut être changé sans conséquence. Le cadre Squared demande une validation pour les opérations structurelles et sensibles.

Rechercher les références

  1. Identifiez le scénario qui doit changer et les pages concernées.
  2. Recherchez les identifiants d’éléments, champs et fonctions utilisés par ce scénario.
  3. Vérifiez les appels de données et les permissions attendues.
  4. Préparez un changement limité et un retour arrière.
  5. Testez avant publication dans le contexte autorisé.

Ne renommez pas un identifiant pour harmoniser l’affichage d’un label : ce sont deux informations distinctes.

Protéger les données

Une vérification dans l’interface ne remplace pas une autorisation côté service. Ne placez pas de clé privilégiée dans un code envoyé au navigateur et ne désactivez pas des permissions pour faire passer un test.

Vérifier les scénarios proches

Contrôlez le cas nominal, les données absentes, une erreur réseau et les rôles concernés. Consultez les messages techniques sans les publier avec des secrets. Une correction qui compile n’est pas automatiquement validée pour le parcours complet.

Transmettre le changement

Décrivez les éléments touchés, les tests et les limites. Mettez à jour la documentation lorsque le comportement visible change. Consultez Architecture, Tests et Secrets avant une intervention plus large.
