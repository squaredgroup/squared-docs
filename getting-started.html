Bien démarrer

Comprendre le rôle du Squared Help Center et savoir immédiatement où chercher, où poser une question et où signaler un problème.

À quoi sert le Help Center

Le Squared Help Center centralise les réponses qui doivent être faciles à retrouver : documentation produit, procédures, règles de design, méthodes techniques, sécurité, support et communauté.

Le principe est simple : chercher d’abord, demander ensuite, puis escalader uniquement si nécessaire.

1. Commencer par la recherche

Utilisez ⌘K sur Mac, Ctrl+K ailleurs, ou la touche /. La recherche couvre les guides principaux, les procédures et les accès rapides.

  • Recherchez l’action : « publier », « responsive », « CMS ».
  • Recherchez le symptôme : « lien cassé », « page introuvable ».
  • Recherchez le produit : « Workspace », « Wix », « Design System ».

2. Choisir le bon canal

Documentation : réponse stable et vérifiée. Communauté : question générale, idée ou échange. Ticket public : bug précis et reproductible. Support privé : donnée confidentielle ou demande qui ne doit pas être publique.

Règle

Ne publiez jamais de donnée client, mot de passe, token, clé API ou information personnelle sensible sur GitHub public.

3. Comprendre les niveaux d’intervention

N1 — autonome : contenu et actions cadrées. N2 — validation : design, navigation ou comportement. N3 — réservé : architecture, code, permissions, données sensibles ou domaines.

Par où continuer

  • Wix Studio pour les sites.
  • Squared Workspace pour l’ERP.
  • Design System pour l’UI.
  • Process & Ops pour la méthode.
  • Support si vous êtes bloqué.
