Choisir le bon canal pour demander de l’aide

Posez une question utile sans exposer votre compte, vos documents ou les informations d’un client.

Guide pratiqueContenu relu · 26.09.2026
Pour qui ?Membres du Help Center

Commencer par le résultat attendu

Avant d’écrire, formulez ce que vous essayez de faire. « Ouvrir le livrable partagé du projet » permet d’orienter l’aide plus facilement que « cela ne marche pas ». Vérifiez les guides pratiques et cherchez le message d’erreur exact sans y joindre de secret.

Forum ou demande privée ?

Utilisez le forum pour une question générale, un retour d’expérience ou une suggestion partageable. Utilisez le support privé pour un accès, une donnée personnelle, un projet client ou une pièce confidentielle. Un problème général peut devenir privé si sa reproduction nécessite de révéler vos données.

En cas d’impossibilité de connexion, le parcours de récupération d’accès reste disponible sans ouvrir au préalable un ticket connecté.

Préparer les informations utiles

Indiquez le produit, la page ou la rubrique, l’appareil, l’action tentée, le résultat observé et le résultat attendu. Ajoutez le message exact et les vérifications déjà effectuées. Séparez vos observations des hypothèses : « le bouton ne répond pas après un clic » est une observation ; « le serveur est en panne » doit être vérifié.

Une capture n’est utile que si elle montre le problème mieux que le texte. Recadrez-la et masquez les informations non nécessaires, sans masquer le message d’erreur pertinent.

Exemple de demande

Contexte : Workspace web, rubrique Documents, sur téléphone. Action : ouvrir un fichier partagé. Résultat : le détail s’ouvre, mais le fichier ne se charge pas. Attendu : pouvoir consulter le document. Déjà vérifié : bon compte, bon projet, second essai après retour de la connexion.

Dans une demande privée, ajoutez la référence de l’élément si elle est nécessaire. Dans le forum, remplacez le contexte client par un exemple générique.

Poursuivre l’échange

Pour créer puis suivre un ticket, l’article de référence est Préparer et suivre une demande privée. Évitez plusieurs demandes concurrentes pour le même problème. Une nouvelle information doit compléter l’échange existant lorsque vous y avez accès.
