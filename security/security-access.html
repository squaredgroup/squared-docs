Demander et revoir les accès nécessaires

Décrivez le besoin précis et gardez les opérations d’administration dans le bon périmètre.

Pour qui ?Intervenants autorisés sur les supports Squared

Définir le besoin

Une demande d’accès doit indiquer le service, le projet ou l’élément, l’action nécessaire et le contexte de travail. « Lire le livrable du projet » est plus précis que « avoir tous les droits ».

Les comptes restent individuels. Ne partagez pas un identifiant pour aller plus vite et ne demandez pas à une personne autorisée de vous transmettre des données hors du canal prévu.

Demander une correction

  1. Vérifiez le compte connecté et le contexte de l’élément.
  2. Retirez les filtres qui peuvent masquer une donnée.
  3. Notez la commande ou la ressource manquante et le message exact.
  4. Envoyez une demande privée au responsable, avec l’action à réaliser.
  5. Après correction, vérifiez le périmètre obtenu sans explorer les données d’autres personnes.

Pour les responsables habilités

Vérifiez l’identité, le rôle et le besoin. Attribuez les droits nécessaires, puis faites contrôler le résultat dans le compte concerné. Une modification de rôle peut affecter plusieurs espaces : examinez les droits effectifs, pas seulement l’intitulé choisi.

Dans Workspace web, consultez Membres et Invitations pour les commandes concernées.

Revoir et retirer

Un changement de mission, une fin de collaboration ou une nouvelle responsabilité doit déclencher une revue des accès. Transférez le travail encore ouvert avant de retirer ce qui n’est plus nécessaire. Une révocation d’invitation, une désactivation de membre et une révocation de session ne sont pas interchangeables.

En cas d’accès inattendu

N’ouvrez pas davantage de dossiers pour mesurer l’exposition. Signalez le service et le type d’information aperçu sans recopier les données. Suivez la procédure d’incident.
