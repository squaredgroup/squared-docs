Développement — Architecture

Organiser le code et les dépendances pour réduire les effets de bord.

GuideMis à jour · 18.09.2026

Frontières

Séparer UI, logique métier, données et intégrations lorsque cela améliore réellement la maintenance. Éviter les abstractions sans besoin concret.

Source de vérité

Une donnée ou une règle importante doit avoir une source claire. Les duplications créent rapidement des divergences.

Dépendances

Documenter les services externes critiques et prévoir leur indisponibilité. Une dépendance ne doit pas être implicite.

Évolution

Préférer une architecture capable d’évoluer par ajout de modules plutôt qu’une structure figée qui impose des refontes globales.
