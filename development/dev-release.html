Publier et vérifier une version

Préparez le retour arrière et contrôlez le résultat réellement servi aux utilisateurs.

Référence pratiqueContenu relu · 26.09.2026
Pour qui ?Intervenants autorisés sur les supports Squared

Avant la publication

Identifiez la version à publier, les changements inclus et les services concernés. Vérifiez les tests, les validations nécessaires et les notes de version. Une modification de documentation ne doit pas changer les DNS, l’authentification ou les données privées sans besoin explicite.

Préparer un retour arrière

Conservez une version précédente identifiable et comprenez ce qu’un retour arrière affecterait. Pour des données ou une migration, revenir au code précédent ne suffit pas toujours. Les opérations destructives demandent une procédure propre, pas une improvisation pendant l’incident.

Publier une version cohérente

  1. Vérifiez la branche et le commit validés.
  2. Utilisez le processus de déploiement prévu pour le dépôt.
  3. Suivez les résultats de construction et de publication.
  4. Attendez la fin du déploiement avant de conclure sur le site.
  5. Ouvrez les pages concernées sur le domaine réel et comparez le contenu attendu.

Vérifier après déploiement

Contrôlez les liens, ressources, titres et parcours critiques. Vérifiez qu’une page nouvelle n’affiche pas une ancienne version servie par un cache. Pour les fonctions de compte, testez uniquement les actions autorisées dans le périmètre prévu ; ne créez pas de faux clients ou de vraies commandes pour vérifier un bouton.

Communiquer le résultat

Les notes de version décrivent l’effet pour les membres : nouvelle procédure, erreur corrigée, parcours clarifié. Distinguez « rédigé », « intégré », « déployé » et « vérifié en ligne ». Une fusion réussie n’est pas encore une preuve de publication.

Si la vérification échoue

Qualifiez l’impact, stoppez les changements non essentiels et suivez le retour arrière approprié. Conservez les messages et la version concernée. Consultez Process & Ops pour la coordination et les incidents de sécurité si une exposition est suspectée.
