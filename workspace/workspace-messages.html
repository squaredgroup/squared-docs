Échanger dans Workspace

Choisissez la bonne conversation, envoyez un message utile et vérifiez son envoi.

Guide pratiqueContenu relu · 26.09.2026
Pour qui ?Utilisateurs de Workspace web

Workspace web : les commandes et les accès peuvent différer dans les applications natives.

Avant d’envoyer

Les messages de Workspace doivent être distingués d’un e-mail ou d’un ticket du Help Center. Vérifiez les participants et le contexte. Un texte envoyé dans une discussion peut être lu par les personnes autorisées dans cette conversation ; ne supposez pas qu’une note est privée parce que vous l’avez rédigée depuis un projet.

Retrouver une conversation

  1. Ouvrez Messages dans la navigation.
  2. Utilisez Rechercher une conversation, ou le filtre Non lues pour retrouver un échange.
  3. Ouvrez la discussion et relisez les derniers messages pour éviter une réponse hors contexte.
  4. Utilisez Rechercher dans cette discussion pour trouver un élément précis ou Derniers messages pour revenir à la fin.

Envoyer votre message

Rédigez votre texte dans Écrire un message, puis sélectionnez Envoyer. Attendez que le message apparaisse dans le fil. Si l’envoi échoue ou reste incertain, conservez le texte et vérifiez la conversation avant d’envoyer une seconde copie.

Une bonne réponse indique le sujet, l’information nouvelle et l’action attendue. Par exemple : « Le fichier partagé correspond à la proposition B. Pouvez-vous confirmer le texte du bouton avant que je prépare la version à remettre ? »

Créer une nouvelle conversation

Lorsque Nouvelle conversation est disponible, choisissez les Participants et renseignez le nom lorsque ce champ convient au type d’échange, puis sélectionnez Créer. Vérifiez le contexte créé avant le premier message. Ne multipliez pas les discussions pour une même décision : elles rendent l’historique plus difficile à suivre.

Décision, fichier et confidentialité

Un message « reçu » ne signifie pas « validé ». Pour une validation formalisée dans Workspace, utilisez le guide des validations. Pour un fichier, préférez l’élément partagé et sa version plutôt que plusieurs copies sans référence.

Ne publiez pas de mot de passe, de code de récupération ou de données client inutiles. Un problème d’accès contenant des informations privées se traite via le support privé, pas dans une discussion collective choisie au hasard.
